# Требования к проекту
## Функциональные требования
1. Система принимает название продукта и номер партии.
2. Система позволяет выбрать категорию продукта.
3. Система принимает температуру, pH и массу упаковки.
4. Система позволяет указать результат визуального осмотра.
5. Система проверяет обязательные поля и допустимость числовых значений.
6. Система сравнивает показатели с учебными диапазонами выбранной категории.
7. Система показывает общий статус и объяснение по каждому показателю.
8. Система добавляет выполненную проверку в журнал текущего сеанса.
9. Система показывает счётчики общего числа проверок, успешных проверок и проверок с отклонениями.
10. Система позволяет очистить форму и журнал.

## Нефункциональные требования
1. Интерфейс должен быть понятен пользователю без специальной подготовки.
2. Страница должна адаптироваться к мобильному экрану и экрану компьютера.
3. Приложение должно запускаться в современном браузере без сервера и установки библиотек.
4. Ошибочные данные должны сопровождаться понятным сообщением.
5. Пользовательские строки в отчёте должны экранироваться перед отображением.

## Пользовательские сценарии
**Сценарий A — успешная проверка:** пользователь вводит данные, попадающие в учебные диапазоны, выбирает «Без видимых отклонений», запускает проверку и видит успешный отчёт.

**Сценарий B — обнаружение отклонения:** пользователь вводит температуру вне диапазона или отмечает визуальное отклонение. Система показывает общий статус «Обнаружены отклонения» и выделяет конкретные показатели.

**Сценарий C — ошибочный ввод:** пользователь оставляет обязательное поле пустым либо вводит некорректный pH/массу. Браузерная или JavaScript-проверка просит исправить данные.

## Критерии приёмки
- Все поля доступны и подписаны.
- Категория обновляет отображаемые учебные диапазоны.
- Отчёт показывает статус для четырёх проверок.
- История и счётчики обновляются после проверки.
- Некорректный ввод не создаёт запись в журнале.
- В интерфейсе есть предупреждение о демонстрационном характере диапазонов.
